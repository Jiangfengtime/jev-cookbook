# 数独实时 Jev 实验报告

## 1. 这是什么

把原来固定 seed 的离线回放页改为有后端的实时数独解题台。棋盘生成、选格和校验由代码完成，填数判断来自 `main/.env` 配置的真实 Jev。默认暂停，支持预置题目、自定义 seed / 空格数、单步、连续运行和暂停。

## 2. 实验意义

同时观察模型判断与应用控制：模型选了什么数字、收到哪些约束、返回什么概率，以及暂停或切题时应用是否还会落子。真实 HTTP 报文与棋盘结果对应，避免把本地回放或规则求解结果误认为模型预测。

## 3. 要回答的问题

- 模型是否从配置的服务和模型返回，是否存在离线回退？
- 切换题目是否隔离状态和历史，默认暂停且不自动消耗请求？
- 暂停能否阻止在途响应落子，并停止后续调用？
- 页面显示与复制的是否为完整实际请求、响应，是否保留服务端额外字段？

## 4. 实验怎么做的

2026-10-24 使用仓库 `main/.venv`、typesafe-sdk 0.7.5、`decision-model-preview` 访问 `.env` 配置的阿里云原生 System One 服务。没有使用离线替身。

- 实际运行入门整局，标准与挑战各验证前三步；另发出一次真实请求，在途暂停后确认响应不落子。
- 浏览器验证 case 切换、自定义 seed 42 / 1 空格整局、运行、单步及暂停；核对三个复制按钮的剪贴板内容与完整显示正文一致。
- 8 项单元回归验证实际 SDK 序列化、16 题以下的合法类型、配置端点、敏感字段隐藏、请求失败不回退、并发暂停/切题、错误记忆和旧 CLI 的 gold 类型比较修复。测试的 MockTransport 只用于回归注入，不是应用运行模式。

## 5. Jev 每一步怎么工作

公开棋盘 → MRV 选取空格 → 生成 `state`、1 个 Choice 与 9 个 Noul → 官方 SDK 发起 `/v1/systemone` 请求 → 在 HTTP 钩子采集请求及响应 → 解析 Choice 数字 → 校验并更新棋盘。

模型看到公开棋盘、行列宫排除条件及已证错数字；唯一解、seed、gold 留在引擎中。旧 `boolean` 类型已改为 SDK 支持的 `noul`。错误数字不会写入棋盘，三错终止。

每局有独立 ID 与锁；暂停递增版本，使在途响应仅保留报文、不落子。切换题目先暂停旧局。HTTP/解析错误自动暂停，不补造答案。页面报文来自实际 HTTP 收发钩子，保留额外 JSON 字段和响应头，不使用 SDK 的规范化对象替代原始响应；正文展示为解码后文本。鉴权与 Cookie 隐藏，其他内容不截断。

## 6. 实验结果与说明

| Case | seed | 空格 | 实际请求 | 正确填入 | 失误 | 覆盖 |
|---|---:|---:|---:|---:|---:|---|
| warmup | 1 | 12 | 12 | 12 | 0 | 整局完成，win |
| standard | 7 | 40 | 3 | 3 | 0 | 仅验证前三步，未评测整局 |
| challenge | 11 | 55 | 3 | 3 | 0 | 仅验证前三步，未评测整局 |

在途暂停验证：实际收到 HTTP 200，棋盘步数保持 0，报文 `applied=false`，未落子。浏览器另验证了暂停后步数保持不变、在途响应注明未落子、自定义题目成功完成和三种一键复制。

![实时解题界面与原始 HTTP 报文](figures/live-sudoku.png)

[实测 JSON](artifacts/live_validation_20261024.json)保存固定测试流程的模型、逐题汇总、token 和耗时。浏览器操作产生的额外调用不并入该固定流程的数据。标准与挑战的前三步不能证明完整解题能力；不能从单局成功推断泛化能力。

旧难度与失败对照数据完整保留在 [本地基线报告](EXPERIMENT_LOCAL_BASELINE.md)，明确属于本地裁判实验，不能当作真实 Jev 结果。

## 7. 成本与耗时

固定流程中的三组 case 共 18 次真实请求，响应合计 19,336 input tokens；另有 1 次在途暂停请求及浏览器交互调用。服务未返回 output_tokens，因此显示为未知，不补造为 0。

三组 case 实测单请求耗时 213.9–5133.9 ms，平均 523.1 ms。以上包含服务与 HTTP 往返。费用以实际云服务账单为准，没有套用其他平台定价估算。

## 8. 结论与后续

五项交互要求已实现：真实 Jev 判断、case 切换、运行/暂停、完整报文、复制。实测及回归确认暂停/切题的在途结果不能污染棋盘；失败不回退为替身。

从仓库根目录启动 `main/.venv/bin/python main/07_实战应用/app/sudoku/serve_sudoku.py --port 8803`，访问 `http://127.0.0.1:8803`。后续评估高难度胜率需固定 seed 集合、完整运行各局并保留失败结果；本次没有把部分运行包装成整局评测。
